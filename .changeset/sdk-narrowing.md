**BREAKING:** narrow three pieces of SDK machinery no plugin in practice reaches, so no plugin bundle carries them. Every first-party IIFE shrank: `@triiiceratops/plugin-av` 16,723 → 16,109 gzip bytes, image-manipulation 23,297 → 22,852, image-export 35,277 → 34,909, annotation-editor 38,244 → 37,726, pdf-export 218,914 → 218,339. The ESM builds are unchanged; they externalize the SDK for the consumer's bundler.

**`satisfies` implements three range styles and refuses the rest loudly.** A plugin declares `coreRange` and `pluginApiRange` as an exact version (`1.2.3`), a caret range (`^1.2.3`), or a `>=` lower bound (`>=1.2.3`). Tilde expansion, wildcards, `<`/`<=`/`>`/`=` comparators, space-joined AND and `||` OR sets are gone, and a range using one now **throws** an error naming the range and the three styles that work — surfacing as the activation's `setup` failure on the host's `pluginerror` channel. It throws rather than answering `false` because a range style the SDK cannot read would otherwise be indistinguishable from a genuine incompatibility and would take a working plugin off the page for a reason that is not true. Prerelease ordering is unchanged, so an exact pin on an `rc` and `>=1.0.0-rc.0` both keep meaning what they meant.

**Compatibility failures are one formatted error, not a taxonomy.** `PluginCompatibilityReason` and `collectIncompatibilities` are removed. `PluginCompatibilityError` stays, with its `code`, `pluginName` and `pluginVersion`, and its `message` still names every failed check — which is what core has always shown a host — but it no longer carries a `reasons` array. Nothing outside the SDK's own tests read it.

**`PluginHost` requires its services.** `styles`, `locale`, `ui`, `surface` and `reportError` are no longer optional, and the SDK no longer fills stubs or falls back to throwing and to `console.error` when a host omits one. Core has always supplied all five for every activation it runs, so the fallbacks were unreachable in a hosted viewer while shipping in every plugin bundle. The four `createStub*` factories move from the package entry to `@triiiceratops/plugin-sdk/testing`, beside the conformance harness and the test viewer context — that is where a bare `runActivation` with no viewer behind it is assembled, and `docs/plugin-authoring.md` and `docs/plugin-testing.md` now show it that way.

**New subpath: `@triiiceratops/plugin-sdk/register-shared`.** `@triiiceratops/plugin-sdk/register` bootstraps `window.Triiiceratops` if it is absent, so a plugin script may register before core's runs. A plugin that reads core's shared Svelte runtime off that namespace has no such freedom — its own gate refuses to evaluate the bundle without a core already on the page — so it registers into the namespace core installed and carries no registry of its own. `@triiiceratops/plugin-av`'s IIFE uses it; every other plugin keeps the bootstrapping entry, and third-party plugins should keep using `register`.
