---
'triiiceratops': minor
---

**OpenSeadragon is gone. The viewer ships one renderer, it is first-party, and the image surface is core's own API.**

`openseadragon` has left the runtime dependencies — and with `dompurify` retired below, core now has none at all — putting the self-contained custom element at **410,423 raw / 115,587 gzip / 95,602 Brotli** bytes, still the smallest IIIF viewer in `docs/bundle-size-comparison.md` on all three metrics at once. The image surface is now reached through first-party members on `ViewerState` rather than a pass-through object: viewport commands (`zoomIn`, `zoomOut`, `zoomTo`, `panTo`, `fitBounds`, `fitCanvas`), query-only per-frame reads (`viewportScale`, `viewportCentre`, `viewportBounds`, `containerSize`), `canvasToScreen` / `screenToCanvas` between canvas space and screen space, `setImageAdjustments`, `setViewportInset` to reserve surface edges that fits frame into, `subscribeFrame`, `subscribeSurfaceTap`, and two ways to draw over the image — `registerOverlayLayer` for real DOM (focusable and labelled, ids prefixed with the plugin's own id and disposed with it) and `registerPaintLayer` for pixels drawn in the transform the tiles were drawn with. Multi-canvas rendering arrives with the new renderer: facing-page spreads, composite canvases that paint every painting annotation into its own region, `Choice` selection on tiled canvases, IIIF v2 `viewingHint` on a Canvas, and a `continuous` mode that opens an 800-folio manuscript in O(1) network requests, fills it with real page thumbnails instead of grey boxes, and eases to a folio chosen from the navigator. Annotations are drawn and listed for every canvas on screen rather than only the navigated one, a tap on a shape selects it (`activeAnnotationId`, `setActiveAnnotationId`), and a selection keeps its two-tone connector to the panel row. A plugin's docked panel gains the close button and Escape-to-close every core panel already had, and closing a docked panel returns keyboard focus to the toolbar toggle that opened it.

**Breaking.** `ViewerState.osdViewer`, `ViewerState.notifyOSDReady`, `ViewerConfig.openSeadragonConfig`, and the `osd@5` capability are removed with no successor — a plugin still declaring `osd@5` now fails activation, which is correct, because it needs an object that no longer exists. Readiness is a new signal rather than a rename: `ViewerState.rendererReady` means "the renderer has a sized surface and accepts commands", and viewport commands are no-ops before it while the queries answer `0` / `null`. `ViewerConfig.renderer` replaces the old open options escape hatch with a small closed set of knobs. In `triiiceratops/image-export`, `MULTI_CANVAS_GAP` is no longer exported (`getCanvasDisplayLayouts` takes `gap` as an option, defaulting to what the viewer lays out with) and that function now takes each source's dimensions explicitly instead of reading them off a tile source.

**Security.** IIIF rich text — manifest summaries, metadata values, required statements, attribution, canvas metadata, and `text/html` annotation bodies — is rebuilt from IIIF's own allowlist through a single seam instead of being filtered by DOMPurify's much broader default policy and handed back to `{@html}`; `dompurify` is dropped entirely. Search excerpts (`SearchHit.before`, `match`, `after`) are documented plain text and rendered as text nodes rather than reaching four raw `{@html}` sinks — they are filled by any host `SearchProvider` or remote Content Search service, so a hostile one could previously execute script in the host page. Highlighting still works by wrapping the matched term in a bare, lowercase `<mark>`.
