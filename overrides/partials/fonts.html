{#- The documentation's typefaces, self-hosted. This partial is included from `overrides/main.html` as the theme's `fonts` block, replacing it wholesale. Upstream's version emits a `preconnect` and a stylesheet link to Google's font hosts; `font = false` in zensical.toml switches that off, and this puts the same three faces back under our own origin. No host name appears anywhere in this file, which is the assertion in apps/site/tests/unit/type.test.ts. Each face is declared three times: the full upstream file with no `unicode-range`, then its `latin-ext` and `latin` slices. A browser picks the LAST declared face covering a codepoint, so the slices win for what they carry and the full file is fetched only for a page that paints something outside them. Ordering is the mechanism — the full face must come first, or it is downloaded on every page. No glyph is lost: the full faces are the unmodified originals and remain the fallback, which is what makes this different from dropping glyphs. `node scripts/subset-fonts.mjs` generates the slices and `--check` verifies the committed ones; apps/site/src/app.css carries the same nine rules for the marketing surface. The preloads name the `latin` slices, which is what a page of English reference material actually paints. All three are preloaded here, unlike the marketing site, which preloads the roman alone: a documentation page sets prose, captions and code blocks at once, so all three faces are first-paint faces on this surface. The `| url` filter resolves each path against the page being rendered, so the URLs stay correct at every depth of the version directory. That matters more here than it looks: a published version directory is immutable, and the fonts it names must live inside it — `scripts/docs-publish.mjs` copies them in per version for exactly that reason. A shared path outside the version directory would break every archived version the day it moved. The rules are inline rather than in `docs/stylesheets/triiiceratops.css` so that the faces do not depend on the `extra_css` link, which the theme emits after this block and which is content configuration rather than chrome. Source Serif 4 carries the prose in roman and italic; Source Code Pro is confined to code blocks. Both are shipped as unmodified variable faces, hence the `font-weight` ranges and the absence of any static instance. -#}
