{#- Social-preview metadata (Open Graph + X/Twitter cards), included from the `extrahead` block in overrides/main.html. Zensical has no social/Open Graph plugin — nothing in the theme emits these tags — so the whole set is hand-rolled here. Everything below is plain static HTML on purpose: every scraper that matters (Facebook, X, LinkedIn, Slack, Discord, iMessage, Bluesky, Mastodon, WhatsApp) fetches the document and reads the markup WITHOUT running JavaScript, so a tag injected at runtime is a tag no crawler will ever see. Two rules govern the values: 1. Absolute URLs only. A relative `og:image` or `og:url` is the single most common reason a card renders blank. `page.canonical_url` is already absolute (Zensical builds it from `site_url`, which docs-build.mjs suffixes with the version directory on a versioned build). The image URLs come from `extra.og_image*` in zensical.toml and are absolute there. 2. The image lives at an UNVERSIONED, root-level path, not inside //media/. Scrapers cache preview images by URL for days-to-weeks, so every version of the docs should resolve to the same cached image rather than one copy per release. scripts/docs-publish.mjs copies the files to /social/ for exactly this reason. Pages can override any of it from front matter: `description`, `og_image`, `og_image_alt`, `title`.
